# 4.3 对话智能与 RAG 增强专项验收

本专项用于支撑路演加分项 4.3。目标不是继续扩展更多功能，而是把一条多轮导购链路做深：用户先提出预算和场景，随后补充偏好、反选品牌，再要求对比决策。

最新演示补充：拍照找货已接入真实 VLM；图片先被识别成可编辑购物意图，再进入同一条导购链路。多轮追问会从上一轮商品反推品类/子类，避免“手机追问跳到电脑”“牛奶追问跳到早餐零食”“护肤第三轮变闲聊”。

路演定位：

> 把“推荐咨询”推进到“可解释的购物决策”：系统不仅能搜商品，还能维护上下文、处理否定、展示 RAG 依据、提示评价风险，并基于上一轮商品做对比决策。

## 主验收路径

1. `推荐 300 以内通勤鞋`
2. `要轻便一点的`
3. `如果我更看重耐穿呢`
4. `不要刚才那个品牌`
5. `这两个哪个好`

## 通过标准

| 能力 | 通过标准 |
| --- | --- |
| 多轮上下文记忆 | 后续问题继续继承 `300 以内`、`通勤`、`鞋` |
| 偏好追加 | `轻便`、`耐穿` 会进入 memory/preferences |
| 否定与排除 | `不要刚才那个品牌` 不会被当闲聊，并能基于上一轮主推品牌做排除 |
| RAG 推荐依据 | 商品卡展示用户可读的依据来源、评价摘要和风险提醒 |
| 商品对比决策 | `这两个哪个好` 基于上一轮商品做对比，并给出场景化选择建议 |
| 可解释 trace | `shopping_guide` trace 输出 `effective_constraints`、`memory_snapshot` 和 `guide_quality` |
| 导购深度评估 | `guide_quality` 说明当前类目 SOP、缺失关键信息、证据优先级和低置信度标记 |
| 同类追问约束 | 只补充偏好时继续锁定上一轮品类/子类，不跨品类补位 |
| 多模态意图回填 | VLM 正常时输出品类、颜色、材质、用途等可检索属性；VLM 不可用时降级图片相似检索 |
| 安全流式回复 | 回答不暴露 `sku_options`、商品 ID、知识库补充等内部字段，并以 SSE 小片段推送 |

## 路演讲解口径

这条链路展示的是 Agent 对复杂语义的理解能力：它不是每轮重新检索，而是持续维护用户约束，把“补偏好”“反选”“对比”都合并到同一条购物决策链路里。

RAG 的价值体现在四个地方：

1. 商品卡证据：`evidence` 和 `source_summary` 说明推荐依据。
2. 评价风险：`review_insight` 和“评价提醒”把正负面评价变成用户能理解的提醒。
3. 类目 SOP：`guide_quality` 解释当前品类应该关注哪些证据、还缺哪些槽位。
4. 对比决策：Compare Agent 基于上一轮商品和知识文档，给出场景化选择建议。

多模态和流式体验的定位：

1. 拍照找货不是独立小功能，而是把图片属性转成可确认的导购意图，再复用 RAG 推荐链路。
2. VLM 正常时会参与搜索词扩展和理由展示；异常时降级到图片相似检索，保证演示不崩。
3. 流式回复采用安全版策略：先防内部字段泄漏，再按小片段输出，兼顾稳定性和移动端体验。

现场建议用一句话收口：

> 我们没有平均铺开所有能力，而是把 4.3 做成了一条完整链路：多轮记忆 -> 反选排除 -> RAG 依据 -> 评价风险 -> 对比决策。
