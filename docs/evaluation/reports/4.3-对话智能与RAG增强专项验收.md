# 4.3 对话智能与 RAG 增强专项验收

本专项用于支撑路演加分项 4.3。目标不是继续扩展更多功能，而是把一条多轮导购链路做深：用户先提出预算和场景，随后补充偏好、反选品牌，再要求对比决策。

## 主验收路径

1. `推荐 300 以内通勤鞋`
2. `要轻便一点的`
3. `如果我更看重耐穿呢`
4. `不要刚才那个品牌`
5. `这两个哪个好`

## 通过标准

| 能力 | 通过标准 |
| --- | --- |
| 多轮上下文记忆 | 后续问题继续继承 `300 以内`、`通勤`、`鞋` |
| 偏好追加 | `轻便`、`耐穿` 会进入 memory/preferences |
| 否定与排除 | `不要刚才那个品牌` 不会被当闲聊，并能基于上一轮主推品牌做排除 |
| RAG 推荐依据 | 商品卡展示用户可读的依据来源、评价摘要和风险提醒 |
| 商品对比决策 | `这两个哪个好` 基于上一轮商品做对比，并给出场景化选择建议 |
| 可解释 trace | `shopping_guide` trace 输出 `effective_constraints`、`memory_snapshot` 和 `guide_quality` |
| 导购深度评估 | `guide_quality` 说明当前类目 SOP、缺失关键信息、证据优先级和低置信度标记 |

## 路演讲解口径

这条链路展示的是 Agent 对复杂语义的理解能力：它不是每轮重新检索，而是持续维护用户约束，把“补偏好”“反选”“对比”都合并到同一条购物决策链路里。RAG 的价值体现在商品卡证据、评价风险、规格知识和最终对比建议，而不是只把商品列表扔给用户。新增的 `guide_quality` 可以在调试 trace 里解释“这个类目应该问什么、现在缺什么、证据够不够”，更适合突出 4.3 的深度。
