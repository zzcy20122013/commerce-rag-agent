## 失败样本处理规则

1. 意图错：补充 `intent_cases.csv`，并调整 `IntentRouterAgent` 的规则或分类 prompt。
2. 文本检索错：检查商品文本拼接、FAQ 内容、文档 chunk 和 metadata。
3. 图片检索错：检查商品主图质量、图片 embedding、`product_images` collection 和图搜 case。
4. 推荐错：检查预算、品类、库存硬过滤，以及 rerank 权重。
5. 多轮错：补充 `multi_turn_cases.csv`，调整会话记忆字段和追问识别规则。
6. 回答错：检查生成 prompt 是否要求引用检索上下文，避免脱离知识库发挥。
7. 统一表达错：优先检查 `backend/app/agents/response_composer.py` 和 `RESPONSE_COMPOSER_TASK`。
8. 导购表达错：补充 `smoke_cases.csv`，检查回答是否有明确主推、备选、劝退和可执行建议。
9. 知识缺失：新增或更新 `knowledge_docs` 文档，并重建对应索引。

## Smoke 评测集维护规则

`smoke_cases.csv` 用来快速覆盖端到端关键链路，优先放最容易回归的场景：

1. 单轮推荐：填写 `query`。
2. 多轮推荐：填写 `turn_1` 到 `turn_4`，最终评测最后一轮回答。
3. 严格无匹配：`expected_no_exact_match` 填 `true`，用于检查系统是否明确说明没有严格符合条件的商品。
4. 临时 0 库存：`stock_zero_ids` 填商品 ID，多个用 `|` 分隔；评测期间会临时置为 0，结束后自动恢复。
5. 表达质量：`style_ok` 会检查是否有主推/备选/取舍，以及是否暴露 `商品ID`、`sub_category`、`sku_count` 等系统字段。
6. 统一回复：检查 trace 中是否包含 `response_composer`，以及 `llm_enabled` 状态。
7. 反馈显示：闲聊、错误兜底不应显示赞踩；导购、FAQ、商品推荐类回答可显示赞踩。

## Prompt 更新记录格式

每次改 prompt 都记录：

- 日期
- 修改模块
- 触发失败样例
- 修改前问题
- 修改内容
- 复测结果

## 检索参数变更记录格式

每次改召回或排序参数都记录：

- 日期
- collection
- 变更项
- 变更前
- 变更后
- 影响指标

## 多轮失败样例入库规则

当用户第二轮及后续追问出现以下问题时，必须进入 `multi_turn_cases.csv`：

1. 忘记上一轮预算。
2. 忘记上一轮品类。
3. 忘记上一轮用途。
4. 没有加入新偏好，例如“更轻一点”“更便宜一点”。
5. 推荐结果不再满足历史约束。

## 知识库文档更新规则

知识文档需要记录：

- source_file
- doc_type
- category
- version
- 更新原因
- 生效日期
- 下线日期

营销活动、FAQ、商品详情变化后，需要重新导入文档并运行文本检索评测。
