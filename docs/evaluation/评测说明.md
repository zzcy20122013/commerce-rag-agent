# 质量评测与反馈闭环

## 每周评测流程

1. 更新评测集：补充新增失败样例、典型用户问题和新商品/新活动相关 case。
2. 运行完整评测：

```powershell
cd C:\Users\zzcy2\Desktop\agent\backend
.\.venv\Scripts\python.exe -m app.scripts.run_eval
```

3. 查看 `docs/reports` 下的报告：
   - `eval-summary.md`
   - `text_retrieval_report.md`
   - `image_retrieval_report.md`
   - `recommendation_report.md`
   - `multi_turn_report.md`
   - `feedback_failure_report.md`
4. 将 Top 失败样例按原因归类。
5. 根据失败类型更新 prompt、路由样例、检索参数、知识库文档或商品数据。
6. 重新运行评测，确认关键指标没有回退。

## 失败样本处理规则

1. 意图错：补充 `intent_cases.csv`，并调整 `IntentRouterAgent` 的规则或分类 prompt。
2. 文本检索错：检查商品文本拼接、FAQ 内容、文档 chunk 和 metadata。
3. 图片检索错：检查商品主图质量、图片 embedding、`product_images` collection 和图搜 case。
4. 推荐错：检查预算、品类、库存硬过滤，以及 rerank 权重。
5. 多轮错：补充 `multi_turn_cases.csv`，调整会话记忆字段和追问识别规则。
6. 回答错：检查生成 prompt 是否要求引用检索上下文，避免脱离知识库发挥。
7. 知识缺失：新增或更新 `knowledge_docs` 文档，并重建对应索引。

## Prompt 更新记录格式

每次改 prompt 都记录：

- 日期
- 修改模块
- 触发失败样例
- 修改前问题
- 修改内容
- 复测结果

## 检索参数变更记录格式

每次改召回或排序参数都记录：

- 日期
- collection
- 变更项
- 变更前
- 变更后
- 影响指标

## 多轮失败样例入库规则

当用户第二轮及后续追问出现以下问题时，必须进入 `multi_turn_cases.csv`：

1. 忘记上一轮预算。
2. 忘记上一轮品类。
3. 忘记上一轮用途。
4. 没有加入新偏好，例如“更轻一点”“更便宜一点”。
5. 推荐结果不再满足历史约束。

## 知识库文档更新规则

知识文档需要记录：

- source_file
- doc_type
- category
- version
- 更新原因
- 生效日期
- 下线日期

营销活动、FAQ、商品详情变化后，需要重新导入文档并运行文本检索评测。
