## 当前下一步建议

当前项目已经具备 MVP 链路、真实平台简化数据层、Doubao 文本大模型接入、本地 bge-m3 / Chinese-CLIP 接入路径、商品图片资产、Web Debug、多 Agent 第一版能力和 Android 原生端核心展示能力。

最近新增能力：

1. Android 原生端已支持登录页、主聊天页、侧边栏会话、历史消息加载、重命名会话、真实删除会话、商品卡片、RAG 推荐依据展示、图片上传入口、语音转文字入口和反馈入口。
2. 后端已支持 `GET /api/sessions/{id}/messages`、`PUT /api/sessions/{id}` 和 `DELETE /api/sessions/{id}`。
3. 闲聊 `chitchat` 已改为 Doubao 优先，失败时 fallback。
4. 新增 `ResponseComposer`，所有用户可见回复在返回前统一经过表达层。
5. 新增轻量购物与订单闭环：商品卡片/详情加购，购物车查看、删除、改数量，点击“去结算”进入确认订单页，提交时校验库存、扣减库存、生成待支付订单并清空购物车，售罄商品继续由推荐链路过滤。
6. 新增订单流转能力：我的订单中支持模拟支付、发货、确认收货、退款售后和订单记录删除；删除失败不会在 Android 端伪装成成功。
7. 新增后端测试覆盖会话历史/删除、闲聊、反馈显示规则、ResponseComposer、购物车 checkout、订单流转、订单删除和库存一致性；Android 单测覆盖 SSE 错误、Mock 购物/订单和订单删除失败处理。

现在的主要偏差不是链路是否跑通，而是 Agent 体验和展示细节还需要继续向“真人导购产品”靠拢：

1. 继续补强 Plan 05：用 ResponseComposer 统一对比、商品知识、订单、图搜等路径的最终表达。
2. 同步推进 Plan 08：扩充 smoke 评测集，固定导购表达、多轮约束继承、严格筛选和反馈逻辑。
3. 继续打磨 Plan 06：Android UI 视觉、滚动体验、商品卡片布局、确认订单/我的订单体验、错误提示和真机验证。
4. 待 Agent 回答质量和 Android 体验稳定后，再进入 Plan 07 做正式项目路演界面。
5. Plan 09 继续补 Docker、一键启动、日志和部署说明，作为项目交付前的工程化收尾。

## 下一步执行建议

现在进入：

> **Plan 08：质量评测与反馈闭环扩充** + **Plan 06：Android 展示端体验打磨**

当前不建议直接先做路演界面，因为展示层会把 Agent 回答质量和 Android 体验问题放大。更稳的顺序是：

1. 先用评测集固定核心场景，避免后面改一处崩一处。
2. 同步打磨 Android 展示端，让聊天、会话、商品卡片和错误提示更像正式产品。
3. 再做路演界面，把已经稳定的能力包装出来。
4. 最后做真机体验、Docker 化和工程化部署。
