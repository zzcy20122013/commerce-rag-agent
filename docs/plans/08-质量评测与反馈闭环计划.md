# 质量评测与反馈闭环计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可持续优化的评测体系，跟踪意图识别、文本检索、图片检索、推荐质量、多轮对话逻辑、回答可信度和用户反馈。

**Architecture:** 后端记录每次对话、路由、检索、rerank、推荐、会话记忆和反馈。评测脚本读取固定评测集，离线计算指标并输出报告；人工反馈样本进入失败案例池，反哺 prompt、路由样例、检索参数和知识库文档。

**Tech Stack:** Python, SQLite, Pandas, Pytest, Chroma, LangGraph traces, Markdown/CSV reports.

## 3. 指标定义

| 指标 | 计算方式 |
| --- | --- |
| 意图识别准确率 | `correct_intent / total_cases` |
| 文本 Recall@K | 期望商品或文档是否出现在前 K 个召回结果 |
| 图片 Recall@K | 期望相似商品是否出现在前 K 个图片召回结果 |
| 推荐命中率 | 推荐商品是否满足评测用例约束 |
| 价格约束满足率 | 推荐结果是否全部满足预算 |
| 库存约束满足率 | 推荐结果是否排除无库存商品 |
| 回答引用覆盖率 | 回答中的核心结论是否来自检索上下文 |
| 多轮约束继承准确率 | 第二轮及后续追问是否继承预算、品类、用途、偏好等历史约束 |
| 多轮意图延续准确率 | “有没有更轻一点的”等追问是否被识别为对上一轮导购任务的延续 |
| 多轮推荐一致性 | 后续推荐是否同时满足历史约束和新增约束 |
| 用户点赞率 | `positive_feedback / total_feedback` |
| 点踩原因分布 | 按“不相关”“太贵”“解释不清”“没找到同款”等聚合 |

## 5. 评测报告格式

每次评测输出：

```text
docs/reports/YYYY-MM-DD-eval-summary.md
```

包含：

1. 本次评测数据量。
2. 各项指标。
3. 与上次结果对比。
4. Top 20 失败样例。
5. 建议改进项。

## 6. 验收标准

1. `python -m app.scripts.run_eval` 能一次性跑完所有评测。
2. 至少输出 5 份报告：意图、文本检索、图片检索、推荐质量、多轮对话。
3. 用户点踩样本能导出并关联到推荐日志。
4. 每个失败样例都有 query、expected、actual、trace。

## 7. 闭环规则

失败样本处理顺序：

1. 意图错：补路由样例或调整分类 prompt。
2. 检索错：调整 chunk、metadata、embedding 文本拼接方式。
3. 推荐错：调整硬过滤和 rerank 权重。
4. 多轮错：调整会话记忆字段、约束继承逻辑和追问识别 prompt。
5. 回答错：调整生成 prompt 和引用约束。
6. 图片错：增加商品图质量、主图选择和图片召回评测样例。
7. 知识缺失：新增或更新 `knowledge_docs` 文档，并重建对应索引。
