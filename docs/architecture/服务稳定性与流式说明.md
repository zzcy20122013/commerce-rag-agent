# 服务稳定性与流式说明

本文记录当前后端在导购主链路中的稳定性设计、降级策略、RAG 可解释性和流式输出方式。

## 1. 主链路稳定性

当前聊天入口为 `POST /api/chat/stream`，主链路如下：

1. 写入用户消息并读取会话记忆。
2. 解析反选约束，合并到 `memory.exclusions`。
3. 执行 LangGraph：`intent_router -> 业务 Agent`。
4. 业务 Agent 先产出可兜底的草稿回答、商品卡片、trace 和 memory。
5. ResponseComposer 负责最终话术生成。
6. 通过 SSE 返回 `message`、`trace`、`product_cards`、`done`。

关键原则是：业务 Agent 必须先生成可用草稿，LLM 失败时直接返回草稿，避免接口中断。

## 2. 真流式输出

现在 SSE 的最终回答不再只是把完整答案切成小块。

正常情况下，ResponseComposer 会调用 OpenAI-compatible 的 `stream=true` 接口，逐个读取模型返回的 delta，并立即转成 SSE `message` 事件。

如果出现以下情况，则自动回到草稿回答：

- 未配置 `DOUBAO_API_KEY` / `ARK_API_KEY`
- 流式请求超时
- 模型返回空内容
- HTTP 状态码错误
- 其它模型调用异常

购物车这类事务型回答不会交给 LLM 改写，直接保留确定性回答，避免“加购成功/删除成功”被模型改错。

SSE 连接会记录打开、完成、断开和当前活跃连接数。客户端中途断开时，服务端不会把它当成业务成功完成；如果流式生成过程中出现异常，会返回 `error` 事件，并把错误计入运行统计。

## 3. 超时与降级

LLM 客户端统一使用 `LLM_TIMEOUT_SECONDS` 控制同步和流式请求超时，默认 60 秒。

降级路径：

- LLM 不可用：返回业务 Agent 草稿。
- 图片上传缺失：走 `image_text_fallback`，先说明没收到图片，再按文字需求推荐。
- 严格条件无匹配：明确说明没有严格符合条件，不把超预算商品包装成命中。
- 反选条件过滤后无结果：明确说明已避开用户不想要的点，并建议放宽条件或换相邻品类。

## 4. 统一错误码与运行统计

后端已安装统一错误处理器，HTTP 错误会返回固定结构：

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "错误说明",
    "detail": {},
    "request_id": "请求 ID"
  }
}
```

`request_id` 会优先沿用请求头 `x-request-id`，否则由后端生成，便于把 Android 端报错、后端日志和接口响应对应起来。

运行统计入口：

```text
GET /api/runtime/stats
```

当前统计项包括请求总数、HTTP 状态码分布、错误码分布、SSE 打开次数、完成次数、断开次数和当前活跃连接数。该统计是进程内轻量计数，适合本地开发、项目路演和压测观察，不替代生产级监控系统。

## 5. 并发压测

后端提供一个轻量 SSE 并发压测脚本，用于验证接口能否在多请求并发下正常返回 `done`、统计失败请求，并粗略观察耗时。

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.scripts.stress_sse --concurrency 5 --requests 10
```

如果要提高压力，可以调大 `--concurrency` 和 `--requests`。路演前建议用小并发确认后端、模型 key 和本地索引都处于正常状态。

## 6. Android 网络恢复体验

Android 端收到 HTTP 错误或 SSE 错误事件时，会把失败消息展示在聊天流中，并保留“重试”按钮。点击后会重新发送上一次用户问题，用户不需要手动复制问题。

离线 Mock 仍然保留，用于后端未启动时验证基础聊天、商品卡片、商品详情、加购和提交订单入口。

## 7. RAG 可解释性

商品卡片新增 `evidence` 和 `source_summary` 字段。

当前依据来源包括：

- 商品库结构化字段：价格、评分、销量、库存。
- 用户约束匹配：预算、用途、偏好、反选约束。
- 商品标题/描述/规格：用于解释为什么命中某个偏好。
- 用户评价摘要：用于提示差评风险，例如“刺痛”“敏感肌”等。
- 知识库片段：商品详情、FAQ、用户评论等 `knowledge_docs` 检索结果。

ResponseComposer 会优先使用商品卡片里的推荐理由、`evidence` 和 `source_summary` 组织回答，避免编造商品参数。

## 8. 当前测试覆盖

当前后端测试覆盖：

- 购物车 API 和购物车 Agent。
- 会话历史、重命名、删除。
- ResponseComposer 改写与失败回退。
- 流式 ResponseComposer 的 chunk 输出和失败回退。
- 商品知识 RAG 命中向量知识片段。
- 商品知识 chunk 元数据保留。
- 商品卡片推荐依据字段。
- 反馈闭环评测指标。
- 统一错误响应、运行统计和 SSE 断开统计。

运行命令：

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -q
```

Android 单元测试覆盖网络失败消息和重试入口：

```powershell
cd android
.\gradlew.bat testDebugUnitTest
```
