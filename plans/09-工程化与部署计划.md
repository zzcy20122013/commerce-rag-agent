# 工程化与部署计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将本地原型整理成可复现、可配置、可测试、可部署的工程，支持 Docker Compose、本地索引重建、日志追踪和后续数据库迁移。

**Architecture:** 保持 FastAPI 单体后端，使用 Docker Compose 管理后端服务和挂载数据目录。配置通过 `.env` 和 Pydantic Settings 管理；日志统一 JSON 输出；提供数据初始化、索引重建、评测运行脚本。

**Tech Stack:** Docker Compose, FastAPI, Pydantic Settings, SQLAlchemy, SQLite, Chroma persistent storage, Pytest, Ruff, JSON logging.

---

## 1. 范围

包含：

- 配置管理
- 日志规范
- 错误处理
- Dockerfile
- Docker Compose
- 数据目录挂载
- 索引重建脚本
- 测试命令
- 代码格式化
- SQLite 到 PostgreSQL 的迁移预留

不包含：

- Kubernetes
- 云服务器自动扩缩容
- CI/CD 平台集成
- 多服务拆分部署

## 5. 验收标准

1. `make dev` 能启动后端。
2. `make test` 全部通过。
3. `make seed` 能初始化 SQLite。
4. `make ingest-text` 能创建 Chroma 文本 collection。
5. `docker compose up backend` 能启动服务。
6. Docker 模式下 `/health` 正常。
7. 停止容器后，SQLite 和 Chroma 数据仍保留在挂载目录。

## 6. 运维约定

本地开发数据目录：

```text
backend/app/data/
  app.sqlite
  chroma/
  product_images/
  uploads/
```

索引重建顺序：

1. `make seed`
2. `make ingest-text`
3. `make ingest-images`
4. `make eval`

故障排查顺序：

1. `/health`
2. `.env`
3. SQLite 文件是否存在
4. Chroma collection 是否存在
5. Doubao / Ark Key 是否有效
6. 模型文件是否下载成功
